# 7. Стратегия тестирования

## 7.1. Пирамида тестирования

```
       /\
      /E2\        — нет (вне scope курсовой)
     /----\
    / комп  \     — нет (вне scope курсовой)
   /--------\
  /  unit    \    — основа: 31 тест на критичные модули
 /------------\
```

Курсовая работа фокусируется на **unit-уровне** — самой дешёвой и быстрой ступени пирамиды. Покрываются:

- чистые функции расчёта целей по КБЖУ (`calorieCalculator`, `bmrStrategy`);
- адаптер ответа LLM (`responseAdapter`, `parser`);
- утилиты дат (`dateUtils`);
- алгоритмическая функция `getMondayOfWeek` (`foodQueries`).

UI-компоненты, хук-обвязки TanStack Query и Edge Runtime сознательно **исключены** из scope — для них требуется отдельная инфраструктура (Mock Service Worker, deno-test, Playwright), которая не оправдана в рамках курсовой.

## 7.2. Инструменты

| Инструмент | Версия | Назначение |
|------------|--------|------------|
| Vitest | ^2.1.1 | Test runner, ESM-нативный, общий конфиг с Vite |
| @vitest/coverage-v8 | ^2.1.1 | Покрытие через V8 (без инструментации) |
| jsdom | ^24.1.1 | DOM-окружение (для совместимости с UI-кодом в общих модулях) |

## 7.3. Принципы

1. **AAA** (Arrange–Act–Assert) — каждый тест разделён на 3 фазы.
2. **Имена-сценарии** — `TC-NN: <что проверяем>` для соответствия таблице ниже.
3. **Без сетевых вызовов** — все провайдеры замокированы или тестируются на ответе-стабе.
4. **Детерминизм** — тесты не зависят от текущего времени (`getFormattedDate` без аргумента проверяется только по форме строки).
5. **Изолированность** — каждый файл `*.test.ts` импортирует только модуль под тестом.

## 7.5. Критерии приёмки

- 100 % тестов проходят (`npm run test:run`);
- покрытие модулей `src/utils/` (без `imageCompression`, `viewTransition`) — ≥ 80 % lines;
- покрытие `src/lib/authClient.ts` — проверяется повтором запроса после 401;
- запуск занимает ≤ 10 секунд на dev-машине.

Фактические значения — в [`docs/08-test-report.md`](08-test-report.md).
